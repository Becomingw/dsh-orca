# 面板

设置 → **Orca 机群**。

## 它是什么

一块**缓存视图**，不是实时视图。宿主按 `panel.pollSeconds`（默认 120 秒）在后台轮询一次，面板只读那份快照，所以：

- 打开面板 **零 SSH**，再快也不会给训练机加负载
- 点「刷新」才强制拉一轮（并发调用会共享同一轮，不会叠加）
- 页头写清「缓存于 N 秒前」，不假装是实时数据

这和 `orca_status` 的关系：工具调用是**按需、一次性**的；面板是**后台、有节奏**的。两者共用同一个 `remote_status`，所以看到的口径一致。

## 内容

| 区块 | 内容 |
|---|---|
| 页头 | 在线台数 / 运行中任务数 / 缓存时间 / 刷新按钮 |
| 主机卡片 | 主机名 + 别名、负载、GPU 张数与平均利用率、显存、磁盘、内存、同步时间；异常时直接显示错误原文 |
| 任务表 | 跨主机合并、按开始时间倒序、最多 25 条：主机 / 任务 / 状态 / 开始 / 结束 / 退出码 |
| 当前配置 | 轮询间隔、主机数、免询问白名单、信任目录（只读） |

状态点：绿 = 正常，黄 = 有任务在跑，红 = 拉取失败。

## 为什么配置是只读的

配置的真值在 profile 的 `cordis.patch.yml`（`- id: orca` 那一行）。面板写它等于改 profile 的补丁层，会触发重新组合——那是另一类操作，不适合放在一个只读面板里。所以面板只展示**当前生效**的白名单和信任目录，改配置去那个文件。

## 数据接口

宿主注册了一个同源路由，面板只跟它说话：

```
GET /dsh-orca/summary            → 读缓存
GET /dsh-orca/summary?refresh=1  → 先拉一轮再返回
POST /dsh-orca/summary           → 同上
```

返回体：`{ generatedAt, lastRoundAt, pollSeconds, polling, hosts[], jobs[], config{} }`。
`hosts[]` 里每台机器是 `{ host, at, ok, error, hostname, load, gpu, disk, memory, running, jobs }`。

路由只监听环回地址（与 Web 服务器同源），不接收凭据，也不触发除这一轮状态探测以外的任何远端动作。

## 成本

一次轮询 = 每台机器一次 `remote_status`，参数固定为 `log_tail_lines: 0`、`job_limit: 5`。8 台机器、120 秒间隔，等价于每台每分钟半个只读探测。

要彻底关掉后台轮询：`panel.pollSeconds: 0`，面板仍可用，只是每次都得点刷新。

## 主机从哪来

- `config.hosts` 非空：只轮询这一组，完全可控。
- `config.hosts` 为空（等于「允许所有 ssh 别名」）：面板从 `~/.ssh/config` 里**自动发现**具体别名，编号机在前、按数字排序，**最多 12 台**（`MAX_PANEL_HOSTS`）。

之所以要上限：`hosts` 为空是一种授权口径，不是「把整个 ~/.ssh/config 都监控起来」的指令。26 个别名全轮询会让共用机群每分钟多出十几个只读探测，收益也不大。想盯更多，就显式写 `hosts`。

给面板挑主机时只认**具体别名**：通配符、`!` 取反、纯 IP 都被跳过——和引擎的校验口径一致。

## 已知限制

- 面板不显示「谁占着 GPU」——`remote_status` 目前没有 `--query-compute-apps`，在共用机器上这是下一步最该补的字段。
- 任务表只覆盖 `job_limit` 条最近的登记，不做分页；历史在 `~/.local/state/remote-fleet/jobs/`。
- 主机卡片不区分「我启动的任务」和「别人的任务」——只有登记过的才会出现在任务表里。
